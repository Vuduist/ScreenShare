# ScreenShare

Удалённое управление и показ экрана по локальной сети в один клик. Главная идея — **доступ раздаёт тот, кем будут управлять**: человек за своим ПК вписывает IP управляющего, жмёт «Дать доступ», и у управляющего сразу появляется рабочий стол этого ПК. Без паролей и всплывающих подтверждений — само действие «дать доступ» и есть разрешение.

Два режима в одном приложении:

* **Дать доступ** — отдать управление своим рабочим столом (мышь + клавиатура) коллеге по его IP.
* **Показать экран** — отдать только картинку, без управления (как было).

Никаких серверов и интернета — всё работает напрямую между двумя компьютерами в одной сети.

## Как пользоваться

Скачайте `screenshare.exe` из [последнего релиза](../../releases/latest) и запустите на обоих компьютерах — установка не нужна. При первом запуске Windows спросит про доступ к сети, нажмите «Разрешить» (нужно для порта `7878`). Свой IP каждый видит в окне строкой «Мой IP».

### Дать коллеге доступ к своему рабочему столу

Делает тот, к чьему компьютеру нужно подключиться:

1. Узнайте IP управляющего (у него в окне строка «Мой IP»).
2. В разделе **«Дать доступ к моему рабочему столу»** впишите этот IP и нажмите **«Дать доступ»**.
3. У управляющего сразу откроется окно с вашим рабочим столом — он управляет мышью и клавиатурой. Пароль и подтверждения не нужны.

Пока доступ открыт, у вас висит красное окошко **«Вашим ПК управляют …»** с кнопкой **«Прекратить доступ»** — оборвать управление можно в любой момент одним кликом.

Управляющему делать ничего не нужно, кроме как держать ScreenShare запущенным: окно управления откроется само, когда ему дадут доступ.

### Показать коллеге свой экран (без управления)

1. В разделе «Показать свой экран коллеге» впишите IP коллеги, выберите экран.
2. **Start показ** → у коллеги откроется окно с картинкой. **Stop показ** закрывает его.

### Запуск с параметрами

* `screenshare.exe --grant 192.168.1.42` — сразу дать доступ управляющему с этим IP.
* `screenshare.exe --share 192.168.1.42 --screen 1` — сразу показать свой экран.

Удобно для ярлыков вида «пустить айтишника к себе».

## Если не подключается

* У управляющего должен быть запущен ScreenShare, и вы должны вписать именно его IP.
* Порт `7878/tcp` должен быть открыт во входящих правилах брандмауэра **на стороне управляющего** (именно к нему идёт подключение). Если при первом запуске нажали «Отмена», добавьте правило вручную (от администратора):

  ```powershell
  netsh advfirewall firewall add rule name="ScreenShare" dir=in action=allow protocol=TCP localport=7878
  ```

* Компьютеры должны быть в одной сети (или между сетями должна быть маршрутизация).

## Безопасность — прочитайте перед тиражом по компании

Это инструмент для доверенной локальной сети, а не замена TeamViewer/AnyDesk для доступа через интернет.

* **Доступ всегда открывает сам управляемый.** Никто не может подключиться к чужому ПК и захватить его: управление появляется только после того, как человек за целевым ПК сам вписал IP управляющего и нажал «Дать доступ». Входящих «захватов» нет — программа только отдаёт управление туда, куда указал её собственный пользователь.
* **Оборвать можно в один клик** — индикатором «Прекратить доступ» или кнопкой в главном окне.
* **Нет паролей и подтверждений** — по задумке: ответственность за то, кому дать доступ, лежит на том, кто его даёт (как продиктовать свой ID в TeamViewer). Вписывайте только IP человека, которому доверяете; ошибочный IP отдаст управление не тому.
* **Трафик пока не шифруется.** Картинка и события ввода (включая набираемый текст) идут по сети открытым текстом. В пределах доверенного LAN это приемлемо, но **шифрование канала (TLS) — следующий шаг**, и до него не вводите через управление пароли на удалённой машине в недоверённой сети.
* **Не пробрасывайте порт `7878` в интернет.** Управление нацелено на **основной монитор** управляемого ПК.

### Что пока не поддерживается

* Шифрование канала (TLS) — в планах.
* Выбор монитора для управления (берётся основной).
* Shift-сочетания и выделение Shift+стрелками: обычный ввод текста и сочетания с Ctrl/Alt работают, Shift как удерживаемый модификатор не передаётся, чтобы не искажать ввод символов.
* Передача звука, файлов, буфера обмена — не предусмотрена (только экран и ввод).

## Как это работает

* Управляемый подключается к управляющему по TCP, отдаёт свой экран (JPEG, [xcap](https://crates.io/crates/xcap) + [jpeg-encoder](https://crates.io/crates/jpeg-encoder)) и выполняет приходящие события ввода ([enigo](https://crates.io/crates/enigo)). Неизменившиеся кадры не отправляются, поэтому статичный экран почти не грузит сеть.
* Управляющий (слушает порт) принимает поток, показывает окно рабочего стола и шлёт обратно мышь и клавиатуру.
* Приём — [zune-jpeg](https://crates.io/crates/zune-jpeg), интерфейс — [egui/eframe](https://github.com/emilk/egui), окна экранов — отдельные viewport'ы egui, иконка в трее — [tray-icon](https://crates.io/crates/tray-icon).
* Протокол (режимы показа/доступа, события ввода) описан в начале [`src/net.rs`](src/net.rs) и [`src/control.rs`](src/control.rs).

## Сборка из исходников

Нужен [Rust](https://rustup.rs) (stable).

```bash
cargo build --release
```

Готовый файл: `target/release/screenshare.exe`. Код кроссплатформенный (Windows / Linux / macOS), но проверялся только на Windows.

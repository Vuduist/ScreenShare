# ScreenShare

Показ экрана и удалённое управление по локальной сети в один клик. Два режима в одном приложении:

* **Показ** — отдать свой экран коллеге (только картинка, как было). «О, смотри, что нашёл!» → **Start показ** → у коллеги появляется окно → **Stop**.
* **Управление** — подключиться к ПК коллеги, видеть его экран и управлять мышью и клавиатурой. Только с его подтверждением каждый раз.

Никаких серверов и интернета — всё работает напрямую между двумя компьютерами в одной сети.

## Как пользоваться

Скачайте `screenshare.exe` из [последнего релиза](../../releases/latest) и запустите на обоих компьютерах — установка не нужна. При первом запуске Windows спросит про доступ к сети, нажмите «Разрешить» (нужно для порта `7878`). Свой IP каждый видит в окне строкой «Мой IP».

### Показать свой экран коллеге

1. Введите IP-адрес коллеги, выберите экран.
2. **Start показ** → у коллеги откроется окно «Экран: ИМЯ-ПК (IP)». **Stop показ** закрывает его.

Окно у коллеги можно двигать, менять размер и сворачивать; закрытие лишь прячет его (вернуть — кнопкой «Показать»).

### Управлять ПК коллеги

1. В разделе «Управлять чужим ПК» введите IP коллеги (и пароль доступа, если он его задал).
2. **Подключиться**. У коллеги появится запрос: **«X просит разрешить управление вашим экраном»** с кнопками «Разрешить» / «Отклонить».
3. После «Разрешить» у вас откроется окно с его экраном — мышь и клавиатура в этом окне управляют его компьютером. **Отключиться** завершает сессию.

Пока вашим экраном управляют, у вас видно красное окошко-индикатор «Вашим экраном управляет …» с кнопкой **«Прекратить управление»** — управление можно оборвать в любой момент.

Оба компьютера равноправны: каждый может и показывать, и смотреть, и (с подтверждения) управлять.

Закрытие главного окна сворачивает программу в трей; выход — через меню иконки в трее. Последние введённые адреса и настройки запоминаются.

### Настройки доступа к вашему ПК

Раздел «Доступ к этому ПК» в главном окне:

* **Разрешать удалённое управление** — общий выключатель. Даже когда включено, управление всегда требует вашего подтверждения в момент подключения.
* **Пароль доступа** — необязательный общий пароль. Если задан, его спрашивают у тех, кто подключается к вам (и его же вы вводите при подключении к коллеге). Пустой пароль — подключаться может любой, но управление всё равно начнётся только после вашего «Разрешить».

### Запуск с параметрами

* `screenshare.exe --share 192.168.1.42 --screen 1` — сразу начать показ своего экрана.
* `screenshare.exe --control 192.168.1.42` — сразу запросить управление чужим ПК.

Удобно для ярлыков «показать Пете» / «подключиться к Пете».

## Если не подключается

* На принимающем компьютере должен быть запущен ScreenShare.
* Порт `7878/tcp` должен быть открыт во входящих правилах брандмауэра. Если при первом запуске вы нажали «Отмена», добавьте правило вручную (от администратора):

  ```powershell
  netsh advfirewall firewall add rule name="ScreenShare" dir=in action=allow protocol=TCP localport=7878
  ```

* Компьютеры должны быть в одной сети (или между сетями должна быть маршрутизация).

## Безопасность — прочитайте перед тиражом по компании

Это инструмент для доверенной локальной сети, а не замена TeamViewer/AnyDesk для доступа через интернет.

* **Управление невозможно без подтверждения.** Каждая сессия управления начинается только после того, как человек за целевым ПК нажал «Разрешить». Во время управления у него висит индикатор, и он может оборвать сессию кнопкой.
* **Пароль доступа** (если задан) проверяется до показа запроса — это отсекает посторонние подключения и спам запросами.
* **Трафик пока не шифруется.** Картинка и события ввода (включая набираемый текст) идут по сети открытым текстом. В пределах доверенного LAN это приемлемо, но **шифрование канала (TLS) — следующий шаг перед широким тиражом**, и до него не стоит использовать управление для ввода паролей на удалённой машине в недоверенной сети.
* **Не пробрасывайте порт `7878` в интернет.**
* Управление нацелено на **основной монитор** целевого ПК.

### Что пока не поддерживается

* Шифрование канала (TLS) — в планах.
* Сочетания и выделение с Shift (Shift+стрелки, Ctrl+Shift+…): обычный ввод текста и сочетания с Ctrl/Alt работают, Shift как удерживаемый модификатор не передаётся, чтобы не искажать ввод символов.
* Передача звука, файлов, буфера обмена — не предусмотрена (только экран и ввод).

## Как это работает

* Захват экрана — [xcap](https://crates.io/crates/xcap), кадры кодируются в JPEG ([jpeg-encoder](https://crates.io/crates/jpeg-encoder)) и идут по TCP; неизменившиеся кадры не отправляются, поэтому статичный экран почти не грузит сеть.
* Инжекция мыши и клавиатуры на управляемой машине — [enigo](https://crates.io/crates/enigo).
* Приём — [zune-jpeg](https://crates.io/crates/zune-jpeg), интерфейс — [egui/eframe](https://github.com/emilk/egui), окна экранов — отдельные viewport'ы egui, иконка в трее — [tray-icon](https://crates.io/crates/tray-icon).
* Протокол (режимы показа и управления, события ввода) описан в начале [`src/net.rs`](src/net.rs) и [`src/control.rs`](src/control.rs).

## Сборка из исходников

Нужен [Rust](https://rustup.rs) (stable).

```bash
cargo build --release
```

Готовый файл: `target/release/screenshare.exe`.

Код кроссплатформенный (Windows / Linux / macOS), но проверялся только на Windows.
